# はじめに

本書は、C++標準ライブラリにある`std::fmod`と`std::remainder`の違いを理解するための本です。

そのためにはまず、なぜこの2つの関数が分かれているのかを知る必要があります。その理由は簡単には剰余の定義にあるのですが、ではなぜ剰余の定義によって2つの関数が生まれるのか、剰余の定義はどうなってるのか、と突き詰めていくと丸めにたどり着きます。

そして今度は、剰余と丸めに何の関係があるのか、丸めによって何が変わるのか、そもそも丸めってどうやるのか、などなどを考えていき、剰余って思ったよりも難しいことに気づきます。

そうして剰余と丸めの沼で溺れそうになっているうちに、ふと最初の問いを思い出し、なんとか沼から這い上がって改めて`std::fmod`と`std::remainder`に向き合って考えてみます。

本書はそんな本です。

## お約束など

本書では、プログラミングにおける環境としてC++言語とそれが動作する一般的な環境を仮定して記述されており、サンプルコードなどにおいてもC++（C++26）を使用します。

また、浮動小数点数に言及する箇所が多くありますが、特に指定がないければIEEE754（IEC 60559）に準拠した実行環境であることを仮定し、`double`の表現は`binary64`、`float`の表現は`binary32`であることを仮定します。そうでない環境や条件については基本的に考慮しません。

# 剰余と丸め

## 剰余

剰余とは割り算における余りの数の事です。数学的にはより広く定義することもできますが、本書では実数・整数およびそれらを計算機上で扱う際の整数の表現（二の補数）と浮動小数点数の表現（主にIEEE754）上での剰余のみを考えます。

日本において義務教育を受けている場合はおそらく小学三年生くらいで割り切れない割り算の場合にあまりとして出すという形で教えられ、そこで確固としたメンタルモデルが築かれているのではないかと思います。この剰余の定義は次のようになります

> ある整数$a$に対して、$d$を0でない整数とすると
> 
> $$
> a = qd + r　(0 \leq r \lt |d|)
> $$
> 
> を満たす整数$q, r$がただ一つ存在する。この時、$q$を商、$r$を剰余と呼ぶ。

小学校の算数の教えに従うと、$a \div d = q \dots r$のように書くことになります。この剰余は非負であり、その絶対値は除数$d$の絶対値$|d|$よりも小さくなります。

ここでの商$q$は整数ですが、通常の除算で得られる正確な商$\frac{a}{d}$は有理数であり、一般には一致しません。そのため、ここには有理数を整数に変換する処理、すなわち丸め（round）が必要になります。

一旦剰余についての制約（$0 \leq r \lt |d|$）を忘れて、丸め処理を$R(x)$と表すと

$$
q = R(\frac{a}{d}),　a = R(\frac{a}{d}) \times d + r
$$

あるいは剰余について書くと

$$
\begin{align}
r &= a - q \times d \\
&= a - R(\frac{a}{d}) \times d
\end{align}
$$

となります。

$a, d$の値は$a \div d$という式において所与のものであることから、剰余の値は商をどのように選択するかに依存しており、商の選択は丸め処理によって決定されます。

### 用語の整理

ここで一旦剰余周りの用語の整理をしておきます。

本書では、$a \div d = q \dots r$のような割り算と剰余に対して各値の事を次のように呼びます

- $a$ : 被除数（dividend）
- $d$ : 除数（divisor）
- $q$ : 商（quotient）
- $r$ : 剰余（remainder）

本文中では専ら熟語を用い、コード中では対応する英単語を変数名に採用するようにします。また、特定の方式を指定しないような丸め処理/丸め関数のことを`R()`で指定します。

例えば先ほどの除算と剰余と丸めの関係式は次のように書き直されます

$$
\begin{align}
remainder &= dividend - quotient \times divisor \\
&= dividend - R(\frac{dividend}{divisor}) \times divisor
\end{align}
$$

## 丸め処理

剰余は商の丸めの方法によって決まっていると言われても、そこにそれほどの選択肢があるものでしょうか。自明では？と思うのですが、実は実数値を整数値に丸める方法にはいくつかの方法があります。

プログラミングにおける文脈で最も身近なものはIEEE754（ISO/IEC 60559）で規定されている丸めアルゴリズムであると思われます。ここには5種類の丸め方法が定義されています。

- 最近接丸め
    - 中間値は偶数丸め
    - 中間値は0から遠い方向への丸め
- 方向丸め
    - 0方向丸め
    - 正の無限大方向への丸め
    - 負の無限大方向への丸め

丸め処理を、ある実数値（あるいは浮動小数点数値）をそれよりも精度の低い値（より表現桁の短い値）に変換することとすると、入力の値（丸め対象の値）に対して丸め先の値の候補は、入力値を上下に挟み込む最も近い2つの値（浮動小数点数の場合は対象の形式で表現可能な値の集合のうちで最も近い値）に絞られます（非正規化数やNaN、オーバーフローについては考えないこととします）。

最近接丸めは、丸め先の値として入力値との距離が最も近いものを選択します。ただし、2候補に対して等距離となる中間値については別途ルールに従ってどちらかを選択します。

方向丸めの場合は、ルールに従って一律的にどちらかの値を選択します。

ただし、どちらの場合でも丸めの必要がない値（どちらかの候補との距離が0である入力値）については処理を行わないものとします。

これらは浮動小数点数の計算過程で行われる丸め（計算結果を浮動小数点数で表現可能な値に丸める処理）の方法ではありますが、小数点以下の値を整数値に丸める際にも適用できます。ややこしいので、以降特に断らない限り、本書では実数値（浮動小数点数値）を整数値に丸める場合を扱います。

5つの丸め方法を一覧すると次のようになります

| 丸め種別 | 丸め方法 | 中間値 |
|---|---|---|
| 最近接+偶数 | 最も近い候補を採用する | 偶数の候補を採用する |
| 最近接+0から遠い方向 | 最も近い候補を採用する | ゼロから遠い候補を採用する |
| 0方向 | 0に近い側の候補を採用する | 同じ |
| 正の無限大方向 | 正の無限大に近い側の候補を採用する | 同じ |
| 負の無限大方向 | 負の無限大に近い側の候補を採用する | 同じ |

中間値は整数への丸めの場合は端数が`0.5`の値（$n + \frac{1}{2}, (n \in \mathbb{Z})$）の事です。最近接丸めの2種類の方法は、この中間値をどちらの方向に丸めるかが異なっています。

最近接偶数丸めはIEEE754の丸めモードのデフォルトとして指定されており、多くの浮動小数点数演算環境における丸め方法のデフォルトでもあります。このため、最近接偶数丸めの事を単に最近接丸めと呼ぶこともあります。

IEEE754の5種類の丸めを見ていると、丸めという問題にはいくつかの論点があることが分かります。直接は読み取れないものも補うと、主に次の3つの論点に整理できます

1. ある値について、丸める先の値の候補は通常2つ存在する
    - どの候補を選択するか
2. 2つの候補から等距離の中間値をどちらに丸めるか
    - 中間値のための別のルールを設けるかどうか
3. 丸め関数に要求する性質
    - 丸め誤差について
        - 誤差の偏り・バイアス
        - 誤差の上界
    - 符号対称性
        - 正負の値で丸め方法が対称になるか
        - $R(-x) = -R(x)$となるか
          - 絶対値が同じ値同士なら、丸めた値の絶対値も等しくなる
    - 単調性
        - $x \leq y$ならば$R(x) \leq R(y)$

IEEE754の5種類の丸めに加えて、その延長でいくつかの丸めを考えることができます。

- 最近接丸め
    - A: 中間値を偶数に丸める
    - B: 中間値を0から遠い方向へ丸める
    - C: 中間値を奇数に丸める
    - D: 中間値をゼロ方向に丸める
    - E: 中間値を正の無限大方向に丸める
    - F: 中間値を負の無限大方向に丸める
- 非最近接丸め
    - G: 0方向丸め
    - H: 正の無限大方向への丸め
    - I: 負の無限大方向への丸め
    - J: 偶数に丸める
    - K: 奇数に丸める
    - L: 0から遠い方向へ丸める
- M: 確率的丸め（SR-nearness）

JとKの非最近接丸めにおいては、丸めの必要がない値について丸めるものではないものとします。例えば、非最近接偶数丸めにおいて3を2や4に丸めることはありません。また、非最近接奇数丸めにおいて0を1には丸めません。

確率的丸めについては後ほど詳しく解説します。

先ほどの論点から各丸め方式を比較したのが次の表です

|丸め|最近接|中間値|上界|バイアス|対称|単調|
|:--:|:--:|:--:|:--:|:--:|:--:|:--:|

|B|Yes|$\pm \infin$|0.5|符号対称ならなし|`✅`|`✅`|

- 丸め: 丸め方式。直前で列挙していた際に振ってあるアルファベットに対応
- 最近接: 最近接丸めであるか否か
- 中間値: 中間値の丸め方について
    - 「同じ」であれば中間値の丸め方法を特別扱いしない
- 上界: 丸め誤差の絶対値（$|R(x) - x|$）の上界
    - 実数から整数への丸めの場合
- バイアス: 丸め誤差の偏り。
    - 入力分布に依存 : 偏りがある入力分布によってはバイアスが生じうる

    - 正/負 : 非整数入力が正の確率で現れる場合は、バイアスが正/負
- 対称: 符号対称性を持つかどうか
- 単調: 単調性を持つかどうか

### 丸め誤差とバイアス

バイアスとは丸め誤差の偏りの事で、丸め関数に対するある入力分布についての、丸め誤差の期待値（平均値）として定義されます。

ある分布に従う確率変数を$\hat{x}$、値$x$の丸め誤差を$R(x) - x$とすると、バイアスは次のように定義されます

$$
bias = E[R(\hat{x}) - \hat{x}]
$$

バイアスが無い（不偏である）とは、この値が0になること（$E[R(\hat{x}) - \hat{x}] = 0$）です。

バイアスがある丸め方式では丸め誤差が方向性を持つため、丸め誤差の期待値が$b$である場合に$n$回の加算を行った結果の誤差の期待値は$nb$になります（丸めた値を加算していくと加算回数に比例して丸め誤差が蓄積される）。一方、バイアスが無い丸め方式では全体として丸め誤差が方向性を持たないため、そのような一方向の誤差の蓄積を抑えることができます。ただし、これは単一の計算において丸め誤差が無いというわけではなく、数値計算における誤差要因の一部に過ぎません。

例えば、丸め関数への入力の分布が$[0, 1]$の一様分布である場合、最近接丸めでは中間値の扱いに関わらずバイアスはありませんが、同じ区間でも中間値の出現頻度が高い分布の場合にはバイアスが発生する場合があります。ものすごく極端な例では、0.5しか取らない分布の場合は明確にバイアスが発生し、この場合の最近接丸めは中間値の扱いに関わらず非最近接丸めと同等のバイアスと丸め誤差の蓄積が発生します。

値の集合を次のように2つ定義し

$$
X1 = \{ 0,\ 0.25,\ 0.5,\ 0.75,\ 1 \} \\
X2 = \{ -1,-0.75,-0.5,-0.25,0,0.25,0.5,0.75,1 \}
$$

これらの集合の値をそれぞれ1度だけ入力として（各値の出現頻度が一定だとして）各最近接丸めで丸めた際の丸め誤差のバイアス（$\frac{1}{N}\sum_{x \in X} (R(x) - x)$）を計算すると次のようになります

| 方式 | $X1$のバイアス | $X2$のバイアス |
| --- | ---: | ---: |
| 偶数丸め | −0.10 | 0 |
| 0から遠い方向 | +0.10 | 0 |
| 奇数丸め  | +0.10 | 0 |
| ゼロ方向  | −0.10 |  0 |
| $+\infty$ 方向 | +0.10 | +1/9 |
| $-\infty$ 方向 | −0.10 | −1/9 |

非最近接丸めの場合は次のようになります

| 方式 | $X1$のバイアス | $X2$のバイアス |
| --- | ---: | ---: |
| ゼロ方向 | -0.30 | 0 |
| $+\infty$ 方向 | 0.30 | 1/3 |
| $-\infty$ 方向 | -0.30 | -1/3 |
| 偶数 | -0.30 | 0 |
| 奇数 | 0.30 | 0 |
| 0から遠い方向 | 0.30 | 0 |

かなり限定的な値集合による例であり、この結果はあくまで一例です。

入力分布をある値集合上での一様分布とすると、バイアスが無いあるいは小さくなるためには、各値の丸め誤差が打ち消し合う性質が重要になります。

符号対称性を持つ丸め方式では、絶対値が同じ値の符号違いの値の丸め誤差が相殺される（$e(x) = R(x) - x$とすると$e(-x) = -e(x)$となる）ことで丸め誤差が打ち消し合い、トータルでのバイアスが低減されます。

しかし、例えば正負どちらかの値しか出現しないような偏りが入力分布にある場合、符号対称性によるバイアス低減は働きません。その場合でも偶数+0.5の値と奇数+0.5の値の出現確率が等確率であれば、偶数丸めや奇数丸めであれば偶数+0.5と奇数+0.5の値の丸め誤差が相殺されることでトータルでのバイアスが低減されます。これは、最近接ではない偶数/奇数丸めでも得られる特性です。

逆に、非最近接のゼロ方向/ゼロから遠い方向への丸めでは入力分布の符号の偏りによってバイアスが生じえます。これらの丸めにおいては、正の側と負の側での丸め方向が逆になることで丸め誤差が相殺されるためです。同様に、最近接丸めで中間値をゼロ方向/ゼロから遠い方向へ丸める場合も、中間値の符号の偏りによってバイアスが生じえます。

また、中間値の値（小数部が0.5の値）の出現確率が特に高いような分布では最近接丸め方式においてはバイアスが生じる可能性があります。あるいは、偶数+端数と奇数+端数の出現頻度が異なるような分布においては、偶数/奇数丸めにバイアスが生じる可能性があります。

バイアスは丸め関数の特性だけではなく入力分布によっても異なってきます。その丸め処理における入力分布が予め分かっている場合、最近接偶数丸め以外を選択することが合理的となるかもしれません。

### 確率的丸め

確率的丸め（Stochastic Rounding）はかなり特殊な丸めで、乱数によって丸めを行うものです。乱数丸めとも呼ばれます。

確率的丸めは、入力値の上下の最近接表現可能値へ距離に反比例した確率で丸めるものです。

確率的丸めによる丸め関数を$SR(x)$とすると、次のように定義されます

$$
\begin{equation}
  SR(x)=
  \begin{cases}
    \lfloor x \rfloor & \text{with probability $1 - (x - \lfloor x \rfloor)$} \\
    \lceil x \rceil & \text{with probability $x - \lfloor x \rfloor$}
  \end{cases}
\end{equation}
$$

この定義は実数値を整数値に丸める場合のものです。例えば浮動小数点数値の丸めのためには定義を修正する必要があります。

この確率的丸めの方法はSR-nearness（最近接確率的丸め）と呼ばれる方法で、この方法以外にももう一つ、単純に50%の確率でそれぞれ床関数/天井関数を使用するという確率的丸めの方法もあり、こちらはSR-up-or-downと呼ばれているようです。

SR-nearnessがおそらく一般的に使用される確率的丸めの方法ですが、SR-nearnessによる丸めは入力分布によらずバイアスが無いことが最大の特徴です。丸め関数$SR(x)$への入力がどのような分布になっていたとしても、丸め結果には入力の分布に伴う偏りが生じません。

最近接偶数丸めでは丸め関数への入力値について、中間値の値に偏りがある（偶数+0.5の頻度が高いなど）場合に丸め結果にバイアスが生じ、丸めた値を逐次足し合わせていくと丸め誤差が蓄積する場合があります。

SR-nearnessの丸めは入力値の分布によらず丸め結果のバイアスが無いため、一方向の誤差の蓄積を抑えることができます。これは、丸め誤差がランダムに生じることで相殺する性質によるものです（そのように丸め方向の確率を選んでいます）。ただし、丸め誤差がランダムなノイズとしての性質を持つほか乱数生成のコストなどもあるため、通常の計算時の丸め処理としてはあまり向いていないと思われます。

なお、SR-up-or-downによる丸めはSR-nearnessとは異なり、入力分布によってはバイアスが存在します。

入力の実数値$x$を固定し確率的丸めが内部で使用する乱数について期待値・分散の性質を見てみます。最近接丸めを$R_{even}()$とすると

|性質|SR-nearness|最近接偶数丸め|
|---|:--:|:--:|
|期待値 $E[R(x)]$|$x$|一般に$R_{even}(x) \neq x$|
|バイアス $E[R(x) - x]$|$0$|一般に$R_{even}(x) - x \neq 0$|
|分散 $Var[R(x)]$|$p(1-p)$※|$0$|
|誤差の上界|1|0.5|

※$p = x - \lfloor x \rfloor$

この場合、最近接偶数丸めの結果は確定的かつ一意に決まりますが、確率的丸めの結果は確率変数になります。

確率的丸め（SR-nearness）は入力の分布によらずバイアスが生じません。一方で、単調性（他の丸めは満たす）と符号対称性を満たしません（呼び出しごとに独立した乱数を使用する場合に個々の結果について保証されない）。

確率的丸めの用途の一つは、整数計画問題を線形計画問題として解く（線形緩和する）場合に結果として得られる実数解を整数解に丸める際の丸めとして使用することです。乱択丸め法（Randomized Rounding）と呼ばれており、乱択アルゴリズムの一種です。ただし、制約を満たすための追加の工夫が必要な場合があります。

近年重要になっているもう一つの用途は、低精度形式による深層学習時の数値丸めにおける使用です。メモリのボトルネックのために多層NNやLLM等の大規模なNNモデルの学習時にはFP8やさらに短い4bitなどの低精度形式を使用することがかなり一般的になってきています。このような低精度形式の計算においては、重みの更新量が重みの現在値付近の表現間隔に比べて小さい場合、重みに更新量を加算した結果が丸められて更新前の値と等しくなってしまい（いわゆる情報落ちが発生する）、重みの更新が無くなることで学習が停滞します。

例えばFP8（E4M3）では1.0の次の表現可能数は1.125であるため、重みの値が1.0であるときに更新量が0.05の場合、更新結果の1.05は最近接丸めによって1.0になります。この場合、更新量が0.0625を超えないと1.125に更新されることはありません。

確率的丸め（SR-nearness）であれば、更新結果の1.05を確率0.4で1.125へ、確率0.6で1.0へ丸めるため、更新量を期待値として反映できます。

最近接丸めではこのような更新の消失（丸め誤差の蓄積）を回避できませんが、確率的丸めの場合は丸め方向が一定ではないため学習の停滞を回避できます。しかも、確率的丸めの持つランダム性がある種の正則化として働くことでモデルの過学習を防止する効果も得られるようです。

同様に、低精度形式による微分方程式の解法においても繰り返しステップ中の更新量消失の問題を回避するために有効です。

特に機械学習におけるユースケースの強さから、機械学習向けハードウェアでは確率的丸め（SR-nearness）をハードウェアでサポートしている場合があるようです。

### ユークリッド除法

丸めにいくつかの種類があり、剰余もそれによって定義されているとすると、普段剰余として使用しているものが何なのか分からなくなってきます。

数学における剰余を定義する除算はユークリッド除法（Euclidean division）といい、実は最初の剰余の定義

> ある整数$a$に対して、$d$を0でない整数とすると
> 
> $$
> a = qd + r　(0 \leq r \lt |d|)
> $$
> 
> を満たす整数$q, r$がただ一つ存在する。この時、$q$を商、$r$を剰余と呼ぶ。

がユークリッド除法の定義そのものです。剰余に対して$0 \leq r \lt |d|$という制約が指定されていることが重要になります。

この定義に値を当てはめて剰余の制約を満たすように商と剰余を選択することで計算することができ、定義を満たす商と剰余のペアは常に一意になります。しかしこれは定義でありアルゴリズムではありません。

ユークリッド除法のアルゴリズムは、商を選択する丸めにおいて、除数が正の場合は負の無限大方向丸めを、除数が負の場合には正の無限大方向の丸めを選択するものです。

この場合の丸め関数は除数の符号を使用するため1引数関数ではなく2引数関数になります。ユークリッド除法の場合の丸め関数を$R_{divisor}()$とすると、次のように定義されます

$$
\begin{equation}
  R_{divisor}(x)=
  \begin{cases}
    \lfloor x \rfloor & \text{$divisor>0$} \\
    \lceil x \rceil & \text{$divisor<0$}
  \end{cases}
\end{equation}
$$

ここでは、最初に導入した$R()$と合わせるために添え字を利用して$divisor$への依存を表し疑似的な1変数関数としています。

この丸め関数を用いて商は

$$
quotient = R_{divisor}(\frac{dividend}{divisor})
$$

と求められます。

このように選択された商を用いて、先ほどの剰余の定義式から剰余を求めることでユークリッド除法による剰余を得ることができます。

$$
remainder = dividend - quotient \times divisor
$$

例えば$17 \div 5$のユークリッド除法による商と剰余を被除数と除数の符号を変えて計算してみると次のようになります

|被除数|除数|商|剰余|
|---:|---:|---|---|
| $17$ | $5$ | $\lfloor \frac{17}{5} \rfloor = 3$ | $2$ |
| $17$ | $-5$ | $\lceil \frac{17}{-5} \rceil = -3$ | $2$ |
| $-17$ | $5$ | $\lfloor \frac{-17}{5} \rfloor = -4$ | $3$ |
| $-17$ | $-5$ | $\lceil \frac{-17}{-5} \rceil = 4$ | $3$ |

定義にあるように、ユークリッド除法における剰余は被除数と除数の符号によらず非負になります。

整数の商と剰余を求める文脈では、小学校で習う割り算や、数学における除算と剰余は基本的にユークリッド除法によるものです。

C++の`%`演算子による剰余演算においては、被除数が正の領域においての商と剰余はユークリッド除法の結果と一致しますが、被除数が負の領域においては一致しない場合があります。被除数/除数が正負の全領域でユークリッド除法による商と剰余を求める標準的な方法は提供されていません。

### 丸めと通称

本書では丸めの呼び方をその丸め方の特徴に基づいて呼称していますが、いくつかの丸めではより一般的な通称がある場合があります。

|丸め|通称・別名|
|---|---|
|最近接偶数丸め|最近接丸め|
|ゼロから遠い方向への丸め|切り上げ|
|ゼロ方向への丸め|切り捨て|
|正の無限大方向への丸め|天井関数|
|負の無限大方向への丸め|床関数|
|最近接丸め+0から遠い方向への丸め|四捨五入|
|確率的丸め|乱数丸め|

切り上げ/切り捨てについては、負の値をどう扱うに関して異なる場合があります。ここでは、符号を無視して絶対値についてゼロ方向/ゼロから遠い方向への丸めを行うことを切り上げ/切り捨てとしています。符号を考慮して正の値の場合と同じ方向へ増減するようにする場合、正/負の無限大方向への丸めが切り上げ/切り捨てになります。

他の丸めの呼称との一貫性や負数の扱いについての曖昧さのために本書ではこのような通称を基本的には使用しません。

## 丸めによる剰余

少し脱線したものの、丸め処理には思ったよりも色々な方法があることが分かったと思います。

最初に示したように剰余は丸め処理によって定義される側面がありました。ここで、先ほど導入した丸め誤差を用いて剰余を表してみます。まず、符号付の丸め誤差$e(x)$の定義から

$$
\begin{align}
  e(x) &= R(x) - x \\
  R(x) &= e(x) + x
\end{align}
$$

これを剰余の定義式に代入すると

$$
\begin{align}
  remainder &= dividend - R(\frac{dividend}{divisor}) \times divisor \\
  &= dividend - (e(\frac{dividend}{divisor}) + \frac{dividend}{divisor}) \times divisor \\
  &= dividend - (divisor \times e(\frac{dividend}{divisor}) + dividend) \\
  &= - divisor \times e(\frac{dividend}{divisor}) \\
\end{align}
$$

このように、剰余は丸め誤差によっても特徴づけることができます。丸め誤差から剰余を見てみることで、丸めの諸性質と剰余をより関連付けて捉えることができます。

丸め誤差が正になる場合は剰余の符号は除数と逆になり、丸め誤差が負になる場合は剰余の符号は除数の符号と一致する、ということがまずこの式からわかります。

ここまで例示してきた丸め方式においては、実数を整数に丸める際の丸め先の候補は高々2つ（実数$x$に対して$\lceil x \rceil$と$\lfloor x \rfloor$）しかなく、そのため剰余の候補も高々2つです。

丸める前の商を$q = \frac{dividend}{divisor}$とおくと、丸め誤差は$e(q) = R(q) - q$となり、丸めの候補は$\lceil q \rceil$と$\lfloor q \rfloor$の2つなので、それぞれの場合の丸め誤差は

$$
\lceil q \rceil - q \ge 0 \\
\lfloor q \rfloor - q \le 0
$$

となります。

$q$が正の場合でも負の場合でもこれは成り立ち、丸めにおいて上側の候補$\lceil q \rceil$を選択すると丸め誤差$e(q)$は非負になり、下側の候補$\lfloor q \rfloor$を選択すると丸め誤差$e(q)$は0以下になります。

また、丸め誤差の絶対値の上界より、最近接丸めかそうでないかに応じて$|e(q)| \le \frac{1}{2}$か$|e(q)| \lt 1$のどちらかでした。

したがって、$remainder = - divisor \times e(q)$の式において、$e(q)$は丸めの選び方によって$\pm 1$か$\pm \frac{1}{2}$のどちらかで押さえられます。

このように整理すると、剰余の値の範囲が見えてきます。

一時的に除数を$d$、剰余を$r$で表して、最近接丸めか否かと除数の符号に対して2つの丸め先候補の選択に応じた剰余の値の範囲は次のようになります

|丸め / 除数の符号|$\lceil q \rceil$|$\lfloor q \rfloor$|
|---|:---:|:---:|
|最近接丸め / 正| $-\frac{\lvert d \rvert}{2} \le r \le 0$ | $0 \le r \le \frac{\lvert d \rvert}{2}$ |
|最近接丸め / 負| $0 \le r \le \frac{\lvert d \rvert}{2}$ | $-\frac{\lvert d \rvert}{2} \le r \le 0$ |
|非最近接丸め / 正| $-\lvert d \rvert \lt r \le 0$ | $0 \le r \lt \lvert d \rvert$ |
|非最近接丸め / 負| $0 \le r \lt \lvert d \rvert$ | $-\lvert d \rvert \lt r \le 0$ |

この表を見ながら改めてユークリッド除法における丸めの選択を振り返ってみると、剰余が非負になるように適応的に除数の符号に応じた丸め方法を選択していることが分かります。

また、最近接丸めにおいては中間値を2つの候補のどちらに丸めるかについて選択肢がありましたが、中間値の丸め方法の選択は中間値の値についての剰余の符号に影響することが分かります。

丸めの性質の一つである符号対称性も剰余の性質に影響を与えます。

$x$を正の実数値であるとすると、$-x$に対する丸め誤差（$e(x) = R(x) - x$）は

$$
e(-x) = R(-x) + x
$$

となります。丸め$R()$が符号対称性（$R(-x) = -R(x)$）を持つ場合

$$
\begin{align}
  e(-x) &= R(-x) + x \\
  &= -R(x) + x \\
  &= -e(x)
\end{align}
$$

となります。

すなわち、丸め$R()$が符号対称性を持つ場合丸め誤差$e(x)$もまた符号対称性を持ち、$e(-x) = -e(x)$となります。

丸める前の商を$q = \frac{dividend}{divisor}$とおいて、除数はそのままに被除数の符号だけを反転して$-dividend$として$-q$とします。$remainder = - divisor \times e(q)$より

$$
\begin{align}
  -divisor \times e(-q) &= -divisor \times (-e(q)) \\
  &= divisor \times e(q) \\
  &= -remainder
\end{align}
$$

となり、丸め$R()$が符号対称性を持つ場合、剰余の値は被除数の符号に対して符号対称性を持ちます。

逆に除数の符号を変えて$-q$とすると

$$
\begin{align}
  -(-divisor) \times e(-q) &= divisor \times (-e(q)) \\
  &= -divisor \times e(q) \\
  &= remainder
\end{align}
$$

となり、丸め$R()$が符号対称性を持つ場合、剰余の値は除数の符号の影響をうけなくなります。

まとめると、除数$d$と被除数$a$から剰余を求める関数を$Rem(a, d)$と表わし、丸め$R()$が符号対称性を持つ場合、次のことが成り立ちます

- $Rem(-a, d) = -Rem(a, d)$
- $Rem(a, -d) = Rem(a, d)$
- $Rem(-a, -d) = -Rem(a, d)$

すなわち、剰余の値は被除数に対して奇対称性（被除数の符号反転に対する符号対称性）を持ち、除数に対して偶対称性（除数の符号に対する不変性）を持ちます。

丸めの選択は主に、剰余の符号と値の範囲に影響します。これらの性質について、前節で提示した丸め処理毎に一覧してみます。

対象の丸め処理はこちら

ただし、これらの例で剰余が同じ値になっている丸め方法でも、丸める前の商が偶数+端数になると異なった結果になるものがあります。

### 正の値にならない剰余

剰余の性質は丸め処理の選択・設計によって制御可能であることがわかりました。ここでは例として、ユークリッド除法による剰余とは逆に剰余が常に非正（0以下）になるようなものを考えてみます。

このような剰余を得るには、ユークリッド除法の丸めを参考に次のように丸めを選択すれば良さそうです

- 非最近接丸め
- 除数の符号に応じて丸めを選択
    - 除数が正の場合 : 正の無限大方向への丸め
    - 除数が負の場合 : 負の無限大方向への丸め

この場合の丸め関数を$R_{divisor}()$とすると、次のように定義されます

$$
\begin{equation}
  R_{divisor}(x)=
  \begin{cases}
    \lceil x \rceil & \text{$divisor>0$} \\
    \lfloor x \rfloor & \text{$divisor<0$}
  \end{cases}
\end{equation}
$$

この丸めを用いた剰余は通常通りに計算されます

$$
remainder = dividend - R_{divisor}(\frac{dividend}{divisor}) \times divisor
$$

この丸めを用いて$17 \div 5$の商と剰余を計算すると次のようになります

|被除数|除数|商|剰余|
|---:|---:|---|---|
| $17$ | $5$ | $\lceil \frac{17}{5} \rceil = 4$ | $-3$ |
| $17$ | $-5$ | $\lfloor \frac{17}{-5} \rfloor = -4$ | $-3$ |
| $-17$ | $5$ | $\lceil \frac{-17}{5} \rceil = -3$ | $-2$ |
| $-17$ | $-5$ | $\lfloor \frac{-17}{-5} \rfloor = 3$ | $-2$ |

この丸め方式においては

 - $divisor > 0$ : 上側候補を選ぶので、$e(\frac{dividend}{divisor}) \geq 0$
 - $divisor < 0$ : 下側候補を選ぶので、$e(\frac{dividend}{divisor}) \leq 0$

となり、$remainder = -divisor \times e(\frac{dividend}{divisor})$の式より狙い通りに剰余が常に非正になります。

先ほどの表と同様に表すと、この剰余は次の性質を持ちます

|剰余の符号|剰余の範囲|符号反転に関する対称性|
|:--|:--|:--:|
| 常に非正 |$(-\lvert d \rvert, 0]$| `🔺` |

- `🔺` : 被除数の符号に対する符号対称性は持たないが、除数の符号に対する不変性は持つ

これは丸めによって剰余を設計することができるということの一例を示したものですが、このような剰余が具体的に何の役に立つのかは分かりません・・・

### 剰余の性質と丸め

ここまで、丸めによって剰余が決定されるということを説明してきました。しかし、剰余の値に注目すると、欲しい剰余の値についての性質によって丸め方法を選択する、とも言えます。

たとえば

- 剰余を常に非負にしたい -> ユークリッド除法による剰余
- 剰余の絶対値を最小（$|r| \leq \frac{|d|}{2}$）にしたい -> 最近接丸め
- 剰余の符号を除数と同じにしたい -> 負の無限大方向への丸め
- 剰余の符号を被除数と同じにしたい -> 0方向丸め

など。

前節の正の値にならない剰余のように欲しい剰余の性質から考えることで、ここまで挙げたもの以外の丸め方法を考えることができる可能性があります。例えば、丸めの候補は最近接値の2つ以外にも考えることができるかもしれません。

# 整数の剰余

ここからは、前章で理解した剰余に関する知識を踏まえて、C++において使用可能な剰余の計算方法についてみていきます。

この章ではまず、C++における整数除算における剰余についてを扱います。

## `%`演算子

`%`演算子はC++において整数の剰余を計算する際にまず使用することになる基本的な方法です。

C++の`%`演算子による整数の剰余は、先ほどの剰余の定義式において商の丸め方法として非最近接のゼロ方向丸めを採用したものです。`%`演算子による剰余と整数の`/`演算子による除算は一貫して定義されており、`/`演算子による商の丸めの方法も同じです。

例えば、`17 / 5`および`17 % 5`の符号を変えながら計算した結果は次のようになります

|被除数|除数|`/`|`%`|
|---:|---:|--:|--:|
| `17` | `5` | `3` | `2` |
| `17` | `-5` | `-3` | `2` |
| `-17` | `5` | `-3` | `-2` |
| `-17` | `-5` | `3` | `-2` |

非最近接のゼロ方向丸めによる剰余の性質は次のようになります

|剰余の符号|剰余の範囲|
|:--|:--|
|被除数と同符号 | $(-\lvert d \rvert, \lvert d \rvert)$ |

被除数が正の値の間は剰余はおおむね直観的な値になるかと思います。一方で、被除数が負の場合は剰余の値も負の値になります。

有名なところでは、奇数判定の次のようなコードは負の数の入力について意図通りになりません

```cpp
#include <print>

// dividendが負の奇数の場合、dividend % 2は-1になる
if ((dividend % 2) == 1) {
  std::println("{} is odd number.", dividend);
} else {
  std::println("{} is even number.", dividend);
}
```

`%`演算子による剰余計算においての丸めの選択をカスタマイズする方法は提供されていないため、この演算子を使用する限り他の丸め方法による剰余を計算することはできません。

`%`演算子のオペランドは整数型である必要があり、浮動小数点数型では使用できません。オペランドの整数型の符号ありなしが異なる場合、通常の算術変換（Usual Arithmetic Conversions）によって意図通りにならない場合があります。

## `std::div()`

`std::div()`は整数の商と剰余を同時に得る関数です。`<cstdlib>`ヘッダで定義されており、Cの`<stdlib.h>`にある`div()`から来ている関数です。

`std::div()`がCの`div()`と異なる点は、オーバーロードによって`int, long, long long、std::intmax_t`の4つの符号付整数型に対応している点です。Cの場合は`ldiv()`、`lldiv()`、`imaxdiv()`として分かれていました（これらは`std::ldiv()`などとしてC++でも利用可能）。ただし、`std::intmax_t`オーバーロードは`<cinttypes>`で定義されており、`std::intmax_t`が拡張整数型の場合のみ利用可能です。

`std::div()`においての商と剰余の定義は`/`と`%`と同じく丸め方法として非最近接のゼロ方向丸めを採用したものです。

```cpp
int dividend = ...;
int divisor = ...;

auto res = std::div(dividend, divisor);

int quotient = res.quot;
int remainder = res.rem;
```

`std::div()`とそのオーバーロードおよび`std::ldiv()`等の変種は、引数型と同じ型で商と剰余を保持する構造体（集成体）を戻り値として返します。例えば次のような定義になります

```cpp
struct div_t { int quot; int rem; };
```

型名は関数（オーバーロード）ごとに変わる（`ldiv_t`や`imaxdiv_t`のようになる）他、メンバの宣言順は未規定であり、逆になる可能性があります（そのため、構造化束縛の使用が安全ではない）。

`std::div()`は商と剰余を同時に求める関数であり、演算子を使用して記述した時はどうしても2つを分けて書かざるを得ないため商と剰余を同時に計算したい場合はより効率的になる場合もあります。

しかし、x86CPUでは単一の命令で商と剰余を計算できるため、そのような環境ではコンパイラの最適化次第で演算子で（2文で）書いた場合と同等になる可能性があります。

### 歴史

C++11以前は、組み込みの`/`および`%`演算子の商と剰余の計算において、どちらかのオペランドの符号が負である場合の丸め方法は実装定義とされていました。そのため、`-17 / 5`の結果が`-3`になるかの移植性が保証されていませんでした。

一方その時代においても`std::div`の丸め方法は非最近接のゼロ方向丸めとして規定されていました。

```cpp
int dividend = -17;
int divisor = 5;

int quotient = dividend / divisor;  // C++03までは結果は実装定義
int remainder = dividend % divisor; // C++03までは結果は実装定義

auto res = std::div(dividend, divisor);

assert(res.quot == -3);  // ✅
assert(res.rem == -2);   // ✅
```

この問題は欠陥報告として修正されており、その根拠はほとんどのハードウェアにおいてゼロ方向丸めが採用されていたことによります。

### ゼロ方向丸め

C++において除算および剰余計算の丸め方法としてゼロ方向丸めが採用されているのはC言語に由来しており、Cにおいての採用はおそらくほとんどのCPUにおいて除算と剰余を計算する際の丸め方法のデフォルトであるためです。

ゼロ方向丸めのメリットの一つは、丸める前の商の値と丸めた後の商の値について$|quotient| \leq |\frac{dividend}{divisor}|$の関係が成り立つことで$|quotient \times divisor| \leq |dividend|$となるため、$remainder = dividend - quotient \times divisor$の計算においてオーバーフローが発生しない事です（絶対値を外して符号の組み合わせ毎に見ても同様の事が言えます）。

ただし、これには前提となる商の計算自体がwell-formedである必要があります。そうであれば、得られた商から$remainder = dividend - quotient \times divisor$で剰余を計算する際に追加のオーバーフローは発生しません。

このような性質は、言語処理系における剰余計算の実装などにおいて、商を計算する方法さえあれば低コストで対応する剰余が得られるメリットがあり、そのために広く採用されています。

## `std::fmod()`/`std::remainder()`

`<cmath>`にある`std::fmod()`/`std::remainder()`には整数型に対するオーバーロードが用意されており、その剰余計算を直接的に整数型でも利用できます。

その実体は`double`へのキャストを通して`double`型オーバーロードが利用されるため、`double`で表現可能ではない整数値（絶対値が$2^{53}$を超える64ビット整数値の一部など）では正しく剰余を求められ無い点に注意が必要です。

このため、これらの関数による剰余の詳細は次章で解説します。

## P3724 Integer division

※この節ではC++の標準化プロセスに関するある程度の事前知識を想定しており、その詳細は説明しません。気になる場合はisocpp.orgなどを参照してください。

C++における整数の剰余計算における丸めの方法は非最近接ゼロ方向丸めが基本となります。2章で紹介したような多様な丸めを利用しようと思ったら、その多くは自分で実装する必要があります。

その際の素朴な方法として、丸め関数$R()$を用意したうえでそれを用いて商を得て、$remainder = dividend - quotient \times divisor$の関係式を用いて計算するというものがあります。

しかし、前述のようにこの方法は非最近接ゼロ方向丸め以外の丸め方法においてオーバーフローが発生する可能性があるため、剰余を求めるためにこの素朴な式をそのまま使用することはできません。

そして、オーバーフローの発生を回避する実装は存外に難しく、正しく記述するのが困難です（P3724の調査によれば検索して出てくる方法はその多くが正しくない）。また、正しく記述することができても条件分岐がいくつも必要になりコードが複雑化するとともにパフォーマンスが低下します。

整数の除算と剰余計算において、非最近接ゼロ方向丸め以外の丸め方法を選択する需要とそれに対するこのような問題を回避するために、標準ライブラリで特定の丸め方法に対応した除算と剰余計算を行う関数を追加しようとする提案がP3724で議論されています。

- P3724 Integer division（https://wg21.link/p3724）

本書執筆時点での最新のリビジョンはR4で、C++29に向けてLWGレビューを受けています。おそらくC++29で利用可能になると思われます。

この提案では丸め方法が固定された除算・剰余の計算を行う関数をいくつか追加しています。

まずは指定された丸め方法で剰余と商を同時に求める関数が11個追加されます。

```cpp
namespace std {
  template<class T>
  constexpr div_result<T> div_rem_to_zero(T x, T y);

  template<class T>
  constexpr div_result<T> div_rem_away_zero(T x, T y);

  template<class T>
  constexpr div_result<T> div_rem_to_pos_inf(T x, T y);

  template<class T>
  constexpr div_result<T> div_rem_to_neg_inf(T x, T y);

  template<class T>
  constexpr div_result<T> div_rem_euclid(T x, T y);

  template<class T>
  constexpr div_result<T> div_rem_ties_to_zero(T x, T y);

  template<class T>
  constexpr div_result<T> div_rem_ties_away_zero(T x, T y);

  template<class T>
  constexpr div_result<T> div_rem_ties_to_pos_inf(T x, T y);

  template<class T>
  constexpr div_result<T> div_rem_ties_to_neg_inf(T x, T y);

  template<class T>
  constexpr div_result<T> div_rem_ties_to_odd(T x, T y);

  template<class T>
  constexpr div_result<T> div_rem_ties_to_even(T x, T y);
}
```

戻り値型の`std::div_result<T>`は次のように定義される構造体です

```cpp
namespace std {
  template<class T>
  struct div_result {
    T quotient;
    T remainder;

    friend auto operator<=>(const div_result&, const div_result&) = default;
  };
}
```

`std::div()`の戻り値型と異なりメンバの順番は固定されているため、構造化束縛で戻り値を受けることができます。

名前からある程度明らかではありますが、関数と丸め方法の対応は次のようになっています

|関数|丸め|本書との対応|
|---|---|---|
| `div_rem_to_zero()` | ゼロ方向丸め | G |
| `div_rem_away_zero()` | ゼロから遠い方向への丸め | L |
| `div_rem_to_pos_inf()` | 正の無限大方向への丸め | H |
| `div_rem_to_neg_inf()` | 負の無限大方向への丸め | I |
| `div_rem_euclid()` | ユークリッド除法の丸め | N |
| `div_rem_ties_to_zero()` | 最近接ゼロ方向丸め | D |
| `div_rem_ties_away_zero()` | 最近接ゼロから遠い方向への丸め | B |
| `div_rem_ties_to_pos_inf()` | 最近接正の無限大方向への丸め | E |
| `div_rem_ties_to_neg_inf()` | 最近接負の無限大方向への丸め | F |
| `div_rem_ties_to_odd()` | 最近接奇数丸め | C |
| `div_rem_ties_to_even()` | 最近接偶数丸め | A |

非最近接の偶数/奇数丸め（命名規則に従うと`div_rem_to_even()`/`div_rem_to_odd()`）はR1までは提案されていましたが、議論の過程でユースケースを提示できなかったことから削除されています。

また、この提案では商と剰余の値の利用に着目しているため、確率的丸めは検討されていません。

次に、これらの関数に対応する商のみを求める関数が追加されます。

```cpp
namespace std {
  template<class T>
  constexpr T div_to_zero(T x, T y);

  template<class T>
  constexpr T div_away_zero(T x, T y);

  template<class T>
  constexpr T div_to_pos_inf(T x, T y);

  template<class T>
  constexpr T div_to_neg_inf(T x, T y);

  template<class T>
  constexpr T div_euclid(T x, T y);

  template<class T>
  constexpr T div_ties_to_zero(T x, T y);

  template<class T>
  constexpr T div_ties_away_zero(T x, T y);

  template<class T>
  constexpr T div_ties_to_pos_inf(T x, T y);

  template<class T>
  constexpr T div_ties_to_neg_inf(T x, T y);

  template<class T>
  constexpr T div_ties_to_odd(T x, T y);

  template<class T>
  constexpr T div_ties_to_even(T x, T y);
}
```

命名規則は、商と剰余を同時に求める関数に対して途中の`rem_`を取り除いたものになっています。これらの関数は、対応する商と剰余を同時に求める関数に対してその結果から商だけを取り出す薄いラッパ関数として定義されます。

例えば、`div_ties_to_even()`で示すと次のようになります

```cpp
// div_ties_to_even()の実装例
template<class T>
constexpr T div_ties_to_even(T x, T y) {
  return div_rem_ties_to_even(x, y).quotient;
}
```

最後に、ユークリッド除法による剰余を直接求める関数`std::rem_euclid()`が単独で追加されます。

```cpp
namespace std {
  template<class T>
  constexpr T rem_euclid(T x, T y);
}
```

これはユークリッド除法による剰余の需要が他のものと比べると特に強いことによります。そのため、この関数は`std::div_rem_euclid()`のラッパとしては指定されておらず、剰余を直接的に計算する実装を許可しています。


提案文書のappendixにはこれらの関数の参照実装が示されています。C++29や26などの機能を特に使用していないため、C++26以前の環境で実装する場合の参考になるかもしれません。

# 浮動小数点数の剰余

この章では、C++における浮動小数点数の除算における剰余についてを見ていきます。

実数・浮動小数点数の剰余計算においては除数と被除数がともに実数（浮動小数点数）になり、したがってどちらも必ずしも整数値ではなくなります。しかしその場合にも剰余の定義などは整数の場合と同じです。

$$
\begin{align}
remainder &= dividend - quotient \times divisor \\
&= dividend - R(\frac{dividend}{divisor}) \times divisor
\end{align}
$$

$remainder, dividend, divisor$がそれぞれ実数となりますが、実数の剰余においても商の値が丸めによって整数値になる必要があることは変わらないため、この式は引き続き使用可能です。

この式の右辺において、$quotient$以外のものはすべて整数値を取るとは限らないため、剰余の値もまた整数値になるとは限りません。除数か被除数のどちらかが小数である場合、剰余の値も小数になりえます。

しかしその場合でも商の選択に関する議論は変わらないため、2章で行った丸めの選択とそれによる剰余の性質についての議論はそのまま有効です。

ただし、浮動小数点数には`NaN`や`INF`などの特殊な値が存在していますが、本書ではこれらの値が除数もしくは被除数に指定された場合の結果については取り扱いません。cpprefjpやcppreferenceなどで各関数の仕様を参照してください。

## 整数への丸めを行う関数

剰余の性質は商の整数への丸め方法によって定義づけられており、商の整数への丸めを関数を用意すれば通常とは異なる性質を持つ剰余計算を行うことができます。

2章で紹介した丸め方法の全てではないものの、標準には浮動小数点数値から整数値への丸めを行う関数がいくつか提供されています。

```cpp
// doubleオーバーロードの宣言例
namespace std {
  double ceil(double x);

  double floor(double x);

  double trunc(double x);

  double round(double x);

  double nearbyint(double x);

  double rint(double x);
}
```

これらの関数はいずれも、引数`x`の小数部を丸めた整数の浮動小数点数値を返します。

なお、`std::round()`と`std::rint()`には、直接`long`/`long long`型（整数型）へ丸める同系統の関数`std::lround()`/`std::llround()`、`std::lrint()`/`std::llrint()`も用意されています。

これらの関数は

| 関数 | 丸め方法 | 別称 |
|---|---|---|
| `std::ceil()` | 正の無限大方向への丸め | 天井関数 |
| `std::floor()` | 負の無限大方向への丸め | 床関数 |
| `std::trunc()` | ゼロ方向丸め | 切り捨て |
| `std::round()` | 最近接ゼロから遠い方向への丸め | 四捨五入 |
| `std::nearbyint()` | 現在の丸めモードによる丸め |  |
| `std::rint()` | 現在の丸めモードによる丸め |  |

`std::nearbyint()`と`std::rint()`以外の関数は丸め方法が固定されており、現在の丸めモードの影響を受けません。`std::nearbyint()`と`std::rint()`の丸めモードはおそらく、ほとんどの環境で最近接偶数丸めがデフォルトになっていると思われます。

`std::nearbyint()`と`std::rint()`の違いは、その処理に伴って`FE_INEXACT`浮動小数点例外（浮動小数点計算結果を保存するのに丸めを使用したことを表す）を発生させるか否かにあり、`std::nearbyint()`は発生させず、`std::rint()`は引数と結果が異なる場合に発生させる可能性があります。それ以外の動作は同じです。

```cpp
#include <print>
#include <cmath>
#include <cfenv>

void print_round(double v) {
  std::println("ceil({})      = {:.1f}", v, std::ceil(v));
  std::println("floor({})     = {:.1f}", v, std::floor(v));
  std::println("trunc({})     = {:.1f}", v, std::trunc(v));
  std::println("round({})     = {:.1f}", v, std::round(v));
  std::println("nearbyint({}) = {:.1f}", v, std::nearbyint(v));
  std::println("rint({})      = {:.1f}", v, std::rint(v));
  std::println();
}

int main() {
  // 最近接偶数丸めを仮定
  contract_assert(std::fegetround() == FE_TONEAREST);

  print_round(0.5);
  print_round(1.5);
  print_round(-1.5);
  print_round(1.7);
}
```

これらの丸め関数を使用することでそれによる剰余計算を$remainder = dividend - quotient \times divisor$の定義式に従って計算することができますが、この計算を浮動小数点演算として実行することで正確ではなくなる場合があります（詳細は`std::fmod`/`std::remainder`の正確性に関する解説を参照）。

## `std::fmod()`

C++では浮動小数点数の剰余を計算するために`%`演算子を使用することができないため、それが欲しい場合に困って調べるとまず出てくるのが`std::fmod()`ではないかと思います。

```cpp
// doubleオーバーロードの宣言例
namespace std {
  double fmod(double x, double y);
}
```

`std::fmod()`による剰余は、商の選択の丸めとしてゼロ方向丸めを採用したものです。これは整数の場合の`%`演算子や`std::div()`と同じです。このため、`std::fmod()`によって得られる剰余は整数の場合との一貫性があります。

`std::fmod(x, y)`では、`x`が被除数、`y`が除数で、`x / y`の結果をゼロ方向丸めで丸めた商`n`に対して`x - n * y`の値を浮動小数点数値で返します。

`std::fmod()`の剰余計算における商の丸めの方法は固定されており、現在の丸め（浮動小数点環境を通した変更）の影響を受けません。逆に言えば、他の丸め方法で剰余計算を行うことはできません。

## `std::remainder()`

浮動小数点数の剰余が欲しいほとんどの場合は`std::fmod()`で事足ると思われますが、`<cmath>`にはもう一つ剰余を求めるための関数として`std::remainder()`が用意されています。

```cpp
// doubleオーバーロードの宣言例
namespace std {
  double remainder(double x, double y);
}
```

`std::remainder()`による剰余は、商の選択の丸めとして最近接偶数丸めを採用したものです。このため、得られる剰余は`std::fmod()`や`%`演算子とは異なるものになります。

`std::remainder(x, y)`では、`x`が被除数、`y`が除数で、`x / y`の結果を最近接偶数丸めで丸めた商`n`に対して`x - n * y`の値を浮動小数点数値で返します。

`std::remainder()`における商の丸めの方法も固定されているため、現在の丸めが最近接偶数丸め以外に設定されていても影響を受けず、他の丸め方法で剰余計算を行うことはできません。

## `std::fmod()`と`std::remainder()`の比較

2章で行った議論によって、`std::fmod()`と`std::remainder()`の違いはここまでの説明だけで完全に理解できているかもしれませんが、一応まとめておきます。

除数を$d$、被除数を$a$として、それぞれの剰余の性質は次のようになります

|性質 ＼ 関数|`fmod(a, d)`|`remainder(a, d)`|
|---|---|---|
|商の丸め| 非最近接ゼロ方向丸め | 最近接偶数丸め |
|剰余の符号| 被除数`a`と同符号 | 選択される丸め候補による |
|剰余の範囲| $(-\lvert d \rvert, \lvert d \rvert)$ | $[-\frac{\lvert d \rvert}{2}, \frac{\lvert d \rvert}{2}]$ |
|符号反転に関する対称性| `✅` | `✅` |
|丸め方法| 固定 | 固定 |

`std::remainder()`における剰余の符号は選択される丸め候補によって変化し、商の上側候補が選択されると剰余の符号は除数の符号と逆になり、下側候補が選択されると除数の符号と同じになります。特に、中間値の符号は、$l = \lfloor \frac{a}{d} \rfloor$に対して次のようになります

- $l$が偶数 : 剰余の符号は除数の符号と同じ
- $l$が奇数 : 剰余の符号は除数の符号と逆

このため、`std::remainder(a, d)`では被除数`a`の符号によらず、剰余の範囲は$[-\frac{\lvert d \rvert}{2}, \frac{\lvert d \rvert}{2}]$になります。

一方、`std::fmod(a, d)`の場合は被除数`a`の符号によってさらに範囲を狭めることができます。

- `a`が非負 : $[0, \lvert d \rvert)$
- `a`が負 : $(-\lvert d \rvert, 0]$

別の言い方をすると`std::fmod(a, d)`の結果は、`d`の絶対値未満になり、符号は`a`と同じになります。

なお、このような除数もしくは被除数の符号に応じた剰余の値域の制限は、他の非最近接丸め方式の一部においても行うことができます。

### 結果の正確性について

`std::fmod(x, y)`も`std::remainder(x, y)`も剰余の定義を`r = x - n*y`としており、商`n`を求めるために`x/y`を丸める際の丸め方法のみが異なります。そしてこれらの関数はいずれも、`R(x/y)`のように商を求める際に`x/y`の値を浮動小数点数値として処理せず、`n`を`x/y`の正確な値を`R`によって丸めた整数値として求めます。これにより、商の計算において`x/y`の値の丸め誤差が混入せず、結果の剰余の値の計算においても同様に定義通りに求められることで正確なものになります。

すなわち、`std::fmod()`および`std::remainder()`において剰余の計算に使用する商`n`は、浮動小数点除算を実行した結果からではなく数学的に正確な比から求められ、剰余の値も数学的な`x - n*y`の値に正確な値が（浮動小数点演算の結果としてではなく）得られます。

これにより、`x - std::nearbyint(x/y)*y`（丸めモードは最近接偶数丸めとする）のように一見`std::remainder(x, y)`と同等に思える計算式は、`x/y`の結果を浮動小数点数値に丸めているため同等の正確性を得ることができません（中間値付近で結果が異なる場合があります）。

`std::fmod(x, y)`の場合は起こりづらいものの、`x - std::trunc(x/y)*y`のような計算は`std::trunc()`の引数に渡す`x/y`の結果が丸めによって精度を失う場合（小数部が極下位の桁を除いてゼロになるような場合）に異なる結果になる事があります。

ただし、この正確性はあくまで与えられた引数の浮動小数点数値`x, y`に対してのものです。`x, y`に対して丸め等が適用されている場合にそれを補償するようなものではなく、与えられた`x, y`の値に対して剰余を計算する際に追加の丸め誤差等を付加しないという意味です。

また、いずれの関数においてもこの正確性はIEC 60559（IEEE754）と非正規化数がサポートされている場合にのみ保証されます。

## `std::fmod()`と`std::remainder()`のユースケース例

ここまでで把握した理論的な性質の差異が実際の操作・演算としてどのように使用できるかの実感を掴むために、`std::fmod()`と`std::remainder()`それぞれに特有のユースケースの例をいくつか見てみます。

### `std::fmod()` : 周期的な値の正規化

剰余を必要とする多くの用途は、周期的な値の正規化のために使用するのではないかと思われます。`std::fmod()`による剰余はその目的のために非常に素直に使用する事ができます。

周期性を持つ値の典型的な例は角度です。角度の値では、ある角度値$\theta$に対して$\theta + 2\pi$あるいは$\theta + 2n\pi$（$n \in \mathbb{Z}$）は同じ値とみなすことができます。角度は$2\pi$の周期性を持つため、任意の角度値に対して$2\pi$による剰余を求めることで基底の$2\pi$周期の値に正規化することができます。

前後方向を区別する必要がない場合（2次元平面の直線の向き等）はさらに、$\pi$周期の値に正規化することができます。

```cpp
#include <print>
#include <cmath>

int main() {
  std::println("{:>6.2f}", std::fmod(90.0, 180.0));
  std::println("{:>6.2f}", std::fmod(135.0, 180.0));
  std::println("{:>6.2f}", std::fmod(270.0, 180.0));
  std::println("{:>6.2f}", std::fmod(410.0, 180.0));
  std::println("{:>6.2f}", std::fmod(15630.53, 180.0));
}
```
```
 90.00
135.00
 90.00
 50.00
150.53
```

この場合、周期を`180`度として任意の角度値をその周期内の値に正規化しています。

`std::fmod()`では被除数が負の場合は剰余も負になり、剰余の範囲も0を基準に反転するため、負の角度に対しては符号を保ったまま正規化を行うことができます。

```cpp
#include <print>
#include <cmath>

int main() {
  std::println("{:>7.2f}", std::fmod(-90.0, 180.0));
  std::println("{:>7.2f}", std::fmod(-410.0, 180.0));
  std::println("{:>7.2f}", std::fmod(-15630.53, 180.0));
}
```
```
 -90.00
 -50.00
-150.53
```

ただし、負の値の正規化の場合は周期が同じでも剰余の範囲が$(-180, 0]$となるため、正の値の時と同じ向きを同じ方向にそろえる結果にはなりません。負の角度値に対しても$[0, 180)$の値に正規化する場合は符号の補正が必要です。

このような正規化を別の見方をすると、周期が積み重なった値から既に完了している周期の部分を取り除いて未完了の部分の1周期内での位置を求める、のように見ることができます。

例えば2.5秒周期の処理において、全体の経過時間から現在の周期内での時間を求めるということにも使用できます。

```cpp
#include <print>
#include <cmath>

int main() {
  std::println("{:>4.2f}", std::fmod(0.1, 2.5));
  std::println("{:>4.2f}", std::fmod(5.5, 2.5));
  std::println("{:>4.2f}", std::fmod(14234.66, 2.5));
}
```
```
0.10
0.50
2.16
```

### `std::remainder()` : 周期的な基準点からのずれを求める

`std::remainder()`でも同様に周期的な値の正規化を行うことができますが、商の選択に最近接丸めを使用していることによって剰余の絶対値が常に最小になる値が選択され、被除数や除数の符号によらず負の値になり得ます。

このため、`std::remainder()`による周期的な値の正規化においては、最も近い周期の基準点からのずれとして正規化されます。

```cpp
#include <print>
#include <cmath>

int main() {
  std::println("{:>6.2f}", std::remainder(90.0, 180.0));
  std::println("{:>6.2f}", std::remainder(135.0, 180.0));
  std::println("{:>6.2f}", std::remainder(270.0, 180.0));
  std::println("{:>6.2f}", std::remainder(410.0, 180.0));
  std::println("{:>6.2f}", std::remainder(15630.53, 180.0));
}
```
```
 90.00
-45.00
-90.00
 50.00
-29.47
```

この場合、180度の周期に対して±90度の範囲に正規化され、周期の基準点とは0度であり180度です。この値を解釈する時は、180度±で考えるよりも0度±で考えたほうがおそらく分かりやすいと思います。

このような角度表現は、ある基準方向を0度として反時計回りを正、時計回りを負の角度による回転として物体の姿勢を表現する場合に良く使用されます。

例えば、二次元平面におけるある物体の向きをX軸方向を0度として反時計回りを正、時計回りを負の角度による回転とすると、その角度範囲は$[-\pi, \pi)$の様に取ることができます。このように定義した角度の表現において角度の正規化を行う場合には`std::fmod()`よりも`std::remainder()`の方が適しています。

```cpp
#include <print>
#include <cmath>

int main() {
  std::println("{:>7.2f}", std::remainder(45.0, 360.0));
  std::println("{:>7.2f}", std::remainder(-45.0, 360.0));
  std::println("{:>7.2f}", std::remainder(370.0, 360.0));
  std::println("{:>7.2f}", std::remainder(-590.0, 360.0));
  std::println("{:>7.2f}", std::remainder(56380.55, 360.0));
  std::println("{:>7.2f}", std::remainder(-1430.23, 360.0));
}
```
```
  45.00
 -45.00
  10.00
 130.00
-139.45
   9.77
```

この場合はそのまま円周上の値としてマッピングすることができるため理解しやすいのではないかと思います。

`std::remainder()`の注意点は半周期ちょうどの値の扱いです。半周期ちょうど（上記例の場合は180度）の値の場合とはつまり商の計算の丸めにおいて中点の値を丸めている場合です。

```cpp
#include <print>
#include <cmath>

int main() {
  std::println("{:>7.2f}", std::remainder(180.0, 360.0));
  std::println("{:>7.2f}", std::remainder(540.0, 360.0));
}
```
```
 180.00
-180.00
```

`std::remainder(180.0, 360.0)`では除算の結果は`0.5`であり、`std::remainder(540.0, 360.0)`では`1.5`です。`std::remainder()`は最近接偶数丸めによって商を選択するため、前者は`0.0`（下側）、後者は`2.0`（上側）に丸められます。

すなわち、この場合の剰余の符号は商の丸めの下側候補の偶奇によって決まり、それは角度の定義やその値の性質とは無関係です。そのため、$[-\pi, \pi)$のような半開区間に正規化する場合は端点の符号を補正する必要があります。

`std::remainder()`による周期性を持つ値の正規化は別の見方をすると、周期的な基準点に対してその基準からのずれ量を求めている、と見ることもできます。

例えば、一定周期の基準点・格子点上の値について、現在の値が基準点からどれだけずれているかを求めることができます。

```cpp
#include <print>
#include <cmath>

int main() {
  // 周期2.5の基準点からのずれを求める
  std::println("{:>5.2f}", std::remainder(1.0, 2.5));
  std::println("{:>5.2f}", std::remainder(1.25, 2.5));
  std::println("{:>5.2f}", std::remainder(3.75, 2.5));
  std::println("{:>5.2f}", std::remainder(6.4, 2.5));
  std::println("{:>5.2f}", std::remainder(35.23, 2.5));

  std::println();

  std::println("{:>5.2f}", std::remainder(-1.25, 2.5));
  std::println("{:>5.2f}", std::remainder(-6.4, 2.5));
  std::println("{:>5.2f}", std::remainder(-35.23, 2.5));
}
```

```
 1.25
-1.25
-1.10
 0.23

-1.25
 1.10
-0.23
```

最近接偶数丸めは符号対称性を持つため、それによる剰余の符号は被除数の符号が逆になると同じく符号が反転します。

### `std::fmod()` : 上位の桁を取り除く

周期が積み重なった値から既に完了している周期の部分を取り除くという見方の応用として、値からより上位の桁を取り除いて下位桁を取り出すことができます。

```cpp
#include <print>
#include <cmath>

int main() {

  std::println("{:>8.4f}", std::fmod(12345.6789, 100.0));
  std::println("{:>8.4f}", std::fmod(12345.6789, 10.0));
  std::println("{:>8.4f}", std::fmod(12345.6789, 1.0));
  std::println("{:>8.4f}", std::fmod(12345.6789, 0.1));
  std::println("{:>8.4f}", std::fmod(12345.6789, 0.01));
  std::println("{:>8.4f}", std::fmod(12345.6789, 0.001));
}
```
```
345.6789
 45.6789
  5.6789
  0.6789
  0.0789
  0.0089
  0.0009
```

別の例として、秒数から分や時間の単位を取り除くこともできます。

```cpp
#include <print>
#include <cmath>

int main() {
  // 秒数から分未満の秒数を取り出す
  std::println("{:>8.3f}", std::fmod(2350.785, 60.0));

  // 秒数から時間未満の秒数を取り出す
  std::println("{:>8.3f}", std::fmod(56400.923, 3600.0));
}
```
```
  10.785
2400.923
```

ゼロ方向丸めにおいては商の端数、すなわち除数未満の値の部分を切り捨てるため、除数未満の値の部分を剰余としてそのまま取り出すことができます（ただし、入力値を浮動小数点数値で表すことによる誤差が入る場合があります）。これは丸めとして切り捨てを行う`std::fmod()`の性質です。

### `std::remainder()` : 周期を跨ぐ場合の最短の差分を求める

周期性を持つ値同士の差分において、周期を跨ぐ場合の差分は少し厄介です。例えば角度であれば、359度と1度の間の差分は-358度ではなく2度として扱いたい場合の方が多いと思われます。

このような差分に対する正規化では`std::remainder()`がその威力を発揮します。

```cpp
#include <print>
#include <cmath>

int main() {
  {
    const double angle_diff = 1.0 - 359.0;

    std::println("{:>6.1f}", std::fmod(angle_diff, 360.0));
    std::println("{:>6.1f}", std::remainder(angle_diff, 360.0));
  }
  {
    const double angle_diff = 1.0 - 1079.0;

    std::println("{:>6.1f}", std::fmod(angle_diff, 360.0));
    std::println("{:>6.1f}", std::remainder(angle_diff, 360.0));
  }
}
```
```
-358.0
   2.0
-358.0
   2.0
```

先ほどの例のように$[-\pi, \pi)$のような範囲で定義された角度においても、`std::remainder()`では$\pm\pi$を跨ぐような差分の正規化を最短距離で行うことができます。

```cpp
#include <print>
#include <cmath>

int main() {
  {
    const double angle_diff = -180.0 - 179.0;

    std::println("{:>6.1f}", std::fmod(angle_diff, 360.0));
    std::println("{:>6.1f}", std::remainder(angle_diff, 360.0));
  }
  {
    const double angle_diff = 179.0 - (-179.0);

    std::println("{:>6.1f}", std::fmod(angle_diff, 360.0));
    std::println("{:>6.1f}", std::remainder(angle_diff, 360.0));
  }
}
```
```
-359.0
   1.0
 358.0
  -2.0
```

最近接丸めにおいては捨てられる端数が最小になるように丸めが行われるため、そのように得られる剰余の値も絶対値が小さい方が選択されます。差分の値の正規化においては、`std::remainder()`の丸めの最近接性が正規化後の差分として最短の値を選択することに繋がります。

## `std::remquo()`

`std::remquo()`は浮動小数点数値に対して商と剰余を同時に求める（ことができるように見える）関数です。

```cpp
// doubleオーバーロードの宣言例
namespace std {
  double remquo(double x, double y, int* quo);
}
```

剰余は戻り値として返され、商は引数の`quo`の参照先に出力されます。

まず、この関数の返す剰余は`std::remainder(x, y)`と同じもので、そちらと同じく商の丸めの方法を変更することはできません。

次に`*quo`には、`x/y`を最近接偶数丸めによって整数値に丸めた結果の符号と絶対値の下位3ビット分の情報が出力されます。これは絶対値が小さい場合を除いて本来の商の値とは異なります。

`*quo`に出力される商の情報は、規格で最低下位3ビットまで（+符号ビット）が保証されており、実際に何ビットまでが出力されるかは実装定義です。

先ほどの`std::remainder`の例の中に、周期的な基準点からのずれを求めるというものがありました。そこでは、どこかの基準点からどの方向にどの程度ずれているかは分かるものの、どの基準点の近くにいるのかは分かりません。

最も近い（何番目の）基準点の情報は商から得ることができます。

```cpp
#include <print>
#include <cmath>

int main() {
  {
    const double q = std::nearbyint(1.0 / 2.5);
    const double r = std::remainder(1.0, 2.5);

    std::println("{:>3} {:>+5.2f}", q, r);
  }
  {
    const double q = std::nearbyint(6.4 / 2.5);
    const double r = std::remainder(6.4, 2.5);

    std::println("{:>3} {:>+5.2f}", q, r);
  }
  {
    const double q = std::nearbyint(-35.23 / 2.5);
    const double r = std::remainder(-35.23, 2.5);

    std::println("{:>3} {:>+5.2f}", q, r);
  }
}
```
```
  0 +1.00
  3 -1.10
-14 -0.23
```

この例では現在の丸めモードが最近接偶数丸めであることを仮定しています。

なお、`std::nearbyint(x/y)`は`x/y`の結果を浮動小数点数値に丸めてから整数への丸めを行うため、中間値付近において`std::remainder()`の内部での商（`x/y`の正確な値から最近接偶数丸めで商を得る）と異なる場合がありえます。

この例からさらに限定して、基準点を2種類に分けてどちらの基準点に近いかを知りたいとします。例えば、0.0をA、2.5をB、5.0をA、7.5をBというように基準点に対して交互にA/Bのラベルを振り、現在の値がA/Bのどちらの近くにいるかを知りたいとします。

これを知るためには商を求めてその偶奇を見ればわかりますが、この場合商の全部は必要なく、下位1ビットだけが分かれば十分です。

`std::remquo()`はこのために使用できます。

```cpp
#include <print>
#include <cmath>

char get_label(int quo) {
  // 下位1ビットだけを見る
  if ((quo & 1) == 0) {
    return 'A';
  } else {
    return 'B';
  }
}

void print_label_and_diff(double value, double period) {
  int quo;
  const double r = std::remquo(value, period, &quo);

  std::println("{} {:>+5.2f}", get_label(quo), r);
}

int main() {
  print_label_and_diff(1.0, 2.5);
  print_label_and_diff(3.0, 2.5);
  print_label_and_diff(4.0, 2.5);
  print_label_and_diff(-1.0, 2.5);
}
```
```
A +1.00
B +0.50
A -1.00
A -1.00
```

`quo`には商の少なくとも下位3ビット分の情報が出力されているため、下位1ビットは確実に利用できます。

ラベルの数を増やして4種類にして、A(0.0) -> B(2.5) -> C(5.0) -> D(7.5) -> A(10.0)... のようにする場合でも同様に`std::remquo()`の商情報を用いて判定できます。この場合は下位2ビット分の情報だけから判定できます。

```cpp
#include <print>
#include <cmath>
#include <utility>

char get_label(int quo) {
  // 下位2ビットだけを見る
  const int k = quo & 0b11;
  switch(k) {
    case 0b00:
      return 'A';
    case 0b01:
      return 'B';
    case 0b10:
      return 'C';
    case 0b11:
      return 'D';
  };

  std::unreachable();
}

void print_label_and_diff(double value, double period) {
  int quo;
  const double r = std::remquo(value, period, &quo);

  std::println("{} {:>+5.2f}", get_label(quo), r);
}

int main() {
  print_label_and_diff(1.0, 2.5);
  print_label_and_diff(3.0, 2.5);
  print_label_and_diff(4.5, 2.5);
  print_label_and_diff(8.0, 2.5);
  print_label_and_diff(11.0, 2.5);
}
```
```
A +1.00
B +0.50
C -0.50
D +0.50
A +1.00
```

下位3ビットの保証の範囲内では、同様の考え方で8パターンまでの周期の識別が可能です。

C++には最近接偶数丸めによる商と剰余を同時に求める関数が無く、商と剰余が同時に欲しいが商の全部の情報は必要ない場合、商と剰余を個別に求めるよりも`std::remquo()`を使用することで計算を効率化できる可能性があります。

この関数の最も分かりやすい用途は三角関数の引数を簡約することです。三角関数の実装を考える際に角度の周期性を利用して引数の角度値を$[0, 2\pi)$もしくは$[0, \pi)$に簡約して計算することは計算誤差を抑制するなどの点で有効です。

さらに進んで、引数値を$[0, \frac{\pi}{4})$の範囲に簡約して、元の角度値がどの$\frac{\pi}{2}$基準点の近くにいるかの情報を利用して`sin()`/`cos()`関数にディスパッチしたうえで適切な符号を与えることで正しく計算することができます。

この方法の場合、`sin()`/`cos()`関数の実装を$[0, \frac{\pi}{4})$の範囲についてだけ用意しておけば`sin()`/`cos()`関数の実装を完成させることができます。

簡約後の角度値は$[0, \frac{\pi}{4})$に抑えたいので、最近接偶数丸めによる剰余では除数を$\frac{\pi}{2}$にします。この場合の`std::remainder()`による剰余は$[-\frac{\pi}{4}, \frac{\pi}{4}]$になりますが、$sin/cos$がそれぞれ奇関数/偶関数であることを利用すると、`sin(-r) = -sin(r)`、`cos(-r) = cos(r)`であるため、`r`の絶対値を取って$[0, \frac{\pi}{4}]$の範囲だけを入力として、符号は後から補正すればよくなります。

端点$r = \frac{\pi}{4}$の値の扱いについては直接$\frac{1}{\sqrt{2}}$を返すなどの方法もありますが、ここでは単純に簡約後の引数範囲を$[0, \frac{\pi}{4}]$にすることにします。ここまでの説明と若干条件は変わりますが、`std::remquo()`の例としては影響しません。

$2\pi$周期の値を$\frac{\pi}{2}$周期の値に簡約しているため、元の周期を4分割しています。そのため、`std::remquo()`で得られる商情報は4パターンの識別を行えれば良く、前の例と同様に下位2ビットを利用すれば十分です。

入力値`x`に対する`std::remquo(x, pi/2)`で得られる商情報を`quo`、剰余を`r`としたとき、`quo`の下位2ビットの値に対する$sin(\theta)$/$cos(\theta)$の計算の対応は次のようになります

| `quo & 0b11` | $\theta$ | $sin(\theta)$ | $cos(\theta)$ |
|---|---|---|---|
| `0b00`（0） | `r` | `sin(r)` | `cos(r)` |
| `0b01`（1） | $\frac{\pi}{2}$ + `r` | `cos(r)` | `-sin(r)` |
| `0b10`（2） | $\pi$ + `r` | `-sin(r)` | `-cos(r)` |
| `0b11`（3） | $\frac{3\pi}{2}$ + `r` | `-cos(r)` | `sin(r)` |

$\theta$は`r`と`quo`から復元される$2\pi$周期上の位置です。

この対応は加法定理から求めることができます。

加えて、`r`が負の場合は`-sin(abs(r))`のように符号を補正することで、$[0, \frac{\pi}{4}]$の値の範囲内の入力のみから任意の角度に対する`sin()/cos()`の計算を完了することができます。

これらの事を踏まえた実装は次のようになります

```cpp
#include <cmath>
#include <numbers>
#include <utility>

struct sin_cos_result {
  double sin;
  double cos;
};

auto sincos(double rad) -> sin_cos_result {
  constexpr double half_pi = std::numbers::pi / 2.0;

  int quo;
  const double r = std::remquo(rad, half_pi, &quo);
  const double a = std::abs(r);

  // 剰余の符号によるsin(r)の符号補正
  const double sin_r = std::copysign(std::sin(a), r);
  const double cos_r = std::cos(a);

  switch (quo & 0b11) {
    case 0b00:
      return {
        .sin = sin_r,
        .cos = cos_r
      };
    case 0b01:
      return {
        .sin = cos_r,
        .cos = -sin_r
      };
    case 0b10:
      return {
        .sin = -sin_r,
        .cos = -cos_r
      };
    case 0b11:
      return {
        .sin = -cos_r,
        .cos = sin_r
      };
  };

  std::unreachable();
}
```

ここでは三角関数実装として`std::sin()`と`std::cos()`を使用しているものの、それに与える引数`a`は$[0, \frac{\pi}{4}]$の範囲内に制限されています。

なお、このコードはあくまで`std::remquo()`の説明のためのものであるため、実際に使用しようとする場合にいくつか問題点があります（`half_pi`の値の不正確性など）。きちんと実装する場合はPayne–Hanek法などを採用すべきでしょう。

このように、`std::remquo()`は単に商（の一部）と剰余の値を同時に求める関数ではなく、周期性を持つ値をその周期よりさらに短い周期の値として簡約する際に、元の周期内における位置（象限）の情報を同時に取得する関数です。

時間軸上の位置にABCDのラベルを振る例では、10秒周期の値を2.5秒周期（1/4）に簡約する際に、商情報を用いてラベルという形で元の10秒周期内でのおおよその位置を得ています。このおおよその位置に剰余の値を加えることで元の周期上での位置を復元することができます。

三角関数の引数の簡約の例では、$2\pi$周期の角度値を$\frac{\pi}{2}$周期に簡約する際に、商情報を用いて元の$2\pi$周期（円周上）における最も近い$\frac{\pi}{2}$基準点の情報を得ています。
